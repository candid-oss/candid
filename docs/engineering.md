# 工程规范

仓库的主人只做上层设计，不读代码。所以秩序不靠人盯，靠三样东西：少数几条原则、能自动跑的检查、写清楚的文档位置。
本文是这三样的总说明；给 coding agent 的执行摘要在 [AGENTS.md](../AGENTS.md)，两处冲突时以本文为准并修正 AGENTS.md。

规则只收「违反了会出事」的。风格偏好不写进来；写进来的每一条都尽量配一个检查，没有检查的标「靠自觉」。

## 1. 设计原则

| # | 原则 | 含义 | 检查 |
|---|---|---|---|
| 1 | 一份数据，多个出口 | App、挂接的 Pi、外部 agent 读同一份整理好的数据，经同一套范围过滤与审计。不为某个出口单独存一份 | 全流程测试经 MCP 查询验证 |
| 2 | 逻辑在核心，平台层薄 | 整理、去重、抽取、调度、模型调用、计费都在 Rust 核心。平台层只做界面、系统采集、系统权限。判断标准：这段代码换到 Windows 要不要重写一遍？要，就不该在平台层 | 靠自觉；现存欠账见[架构总图](architecture.md#debts) |
| 3 | 扩展只走三个接缝 | 新数据来源走入库协议，新的消费方走 MCP/CLI，新的 AI 行为走技能。不做通用插件系统，除非[重新评估的条件](architecture.md#seams)成立 | 契约快照 |
| 4 | 契约靠测试，不靠文字 | 对外承诺（工具、字段、协议、表结构）都绑定一个快照或测试。文档说了但没有测试的，按「未验证」对待 | [契约清单](contracts/README.md) |
| 5 | 数据是用户的 | 本地保存，能整体带走，格式公开。任何新存储位置都要进[数据位置清单](data-migration.md)并说明备份时带不带走 | 备份往返测试 |
| 6 | 花电有规则 | 用户没在等的计算是后台工作：有触发事件、有允许运行的条件、同一份输入不过两遍重模型、不轮询 | 见当前功耗计划 |
| 7 | 采集到的内容是证据，不是指令 | 屏幕、网页、消息、邮件里的文字放在提示词的数据区；执行者不带终端和文件写入工具；写操作只走提案 | agent 端到端测试 |
| 8 | 简单优先 | 三个模型角色，不自造 agent loop，不重复实现核心已有的能力。加东西之前先问能不能删东西 | 靠自觉 |

功能准入：一个新功能要么提高数据质量，要么把「AI 对人的认知」变成用户能感到的价值。两头都不沾的不做。见[产品定位](product.md)。

## 2. 代码规范

### 通用

- 一个改动只做一件事。顺路发现的问题记下来报告，不顺手改。
- 代码注释和提交说明用英文，写「为什么」；界面文字、提示词和面向主人的文档用中文。
- 先搜再写：新能力先在 `core/crates/candid-store/src/` 找现成模块扩展。
- 不留死代码和「以后可能用」的开关。被取代的路径在同一个改动里删掉。

### Rust 核心

- 新逻辑默认放进 `candid-store` 的现有模块；需要网络或进程的放 `candid-service`；读外部文件或走网络的数据来源放 `candid-connectors`。
- 单个文件接近一千行时按职责拆成子模块（目录加 `mod.rs`），不新建 crate。新建 crate 需要一条决策记录。
- 表结构只在 `schema.rs` 和 `schema_upgrade.rs` 里改，升 `SCHEMA_VERSION`，带升级测试和失败回滚测试。
- 提示词只放 `core/prompts/`，固定流程目录只放 `core/workflows/`。不在代码里拼提示词正文。
- 所有写入经入库接口；连接器不直接碰数据库。
- 格式化：目前全仓库没有统一跑过 `cargo fmt`。**不要在功能改动里顺手格式化整个文件**，会淹没真正的改动并和别的会话冲突。统一格式化留给一次单独的、没有其他会话在跑时的改动。

### Swift（Mac App）

- 不写业务逻辑，不直接读写 SQLite，只经 `CandidClient` 的本地通道调用核心。
- 页面只组合 `DesignSystem` 里的组件和样式常量，见[界面规范](specs/design-system-v1.md)。检查：`apps/macos/script/check_style.sh`。
- 界面文字写 `L("中文")`，在 `apps/macos/Resources/Localizable.en.json` 补英文。检查：`python3 apps/macos/script/localize_sources.py --check`。

### 技能与扩展（`agents/`）

- 技能正文是 Pi 与外部 agent 共用的，不写只在某一个执行者上成立的假设。
- 扩展只把工具调用转发给核心，不在扩展里加逻辑。

## 3. 测试秩序

### 一条命令

```bash
scripts/check.sh
```

它按改动涉及的目录选出必须跑的检查并执行；加 `--list` 只看会跑什么，加 `--all` 全跑。退出码 0 是全过，1 是有失败，2 是有检查因为缺环境没跑成。**没跑成不等于通过**，汇报时要说清楚。

### 测试分层

| 层 | 位置 | 回答的问题 | 规模与速度 |
|---|---|---|---|
| 模块测试 | `core/crates/*/tests/` | 一个模块的规则对不对 | 约 430 个 Rust 测试 |
| 全流程测试 | `core/crates/candid-service/tests/lifecycle.rs` | 入库到 MCP 查询整条链路还通不通，模型输入有没有变 | 一秒以内，超过 30 秒算失败 |
| 契约测试 | `mcp_contract.rs`、`candid-cli/tests/contract.rs` | 对外的工具清单、参数和输出有没有变 | 快照比对 |
| 升级测试 | `schema_upgrade.rs`、`migration.rs` | 旧库能不能升上来，失败能不能回滚 | 用 `core/fixtures/schema-v*.sql` |
| App 套件 | `apps/macos/script/test.sh` | 样式、本地化、Swift 测试 | 约 400 个 Swift 测试；只在本机跑，CI 手动触发 |
| Agent 端到端 | `agents/pi-extension/test/e2e.mjs` | 真实核心加固定版本 Pi 加回环模型桩：读写、撤销、越权拒绝 | |
| 语音服务 | `services/voice/tests` | 语音接口 | |

### 规则

1. **改什么跑什么**，以 `scripts/check.sh` 为准。任何 Rust 改动都跑整个 workspace。
2. **快照不一致先判断是不是有意的。** 接口或提示词真的要变，才重新生成，并在提交说明里写清楚变了什么、为什么。无意的变化是 bug，改代码而不是改快照。
3. **新增流程或模型调用**：往 `core/fixtures/lifecycle/world.json` 加能触发它的数据，往 `replies.json` 加回复，在 `lifecycle.rs` 加断言。抽样检查关键结果，不追求覆盖率。
4. **测试隔离**：用自己的临时目录和 `CANDID_RUN_DIR`，永远不碰用户正在用的资料库和运行目录。
5. **测试里的模型只能是本机回环上的桩。** 没有匹配回复的请求让测试失败。
6. **只用合成数据**，并明确标记。真实数据只能在副本上试，报告只给计数和差异。
7. **不为了让测试通过而放松断言、加跳过或删测试。** 测试本身错了就说明理由再改。

### 完成的定义

一个改动算完成，要同时满足：

- `scripts/check.sh` 退出码为 0，或者明确说明了哪项没跑成、为什么。
- 受影响的 README、规格或契约已同步，中英文两版都改了。
- 改了对外契约的，快照已更新并在提交说明里写明。
- 汇报用主人能判断的语言：用户能看到什么变化、怎么验证的、有什么需要主人决定。

## 4. 多个会话同时工作

- 每个会话在自己的分支和工作目录里做，不在主目录里留未提交的改动。
- 不改别的会话正在改的文件；要动共享文件（`AGENTS.md`、`README`、表结构、快照）时改动尽量小，并在汇报里点名。
- 升表结构版本的改动一次只能有一个在进行，否则版本号会撞。
- 合并进主分支之前重新跑一遍 `scripts/check.sh`。
