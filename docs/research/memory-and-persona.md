## 观察与数据

### 6.1 记忆与人格

先回答用途，再定结构：

- **画像拿来做什么**：调整回答方式、判断什么值得提醒、给建议，还是给外部 agent 当背景？用途不同，所需的结构和证据门槛完全不同。
- **分几层**：事实、偏好、行为模式、特质。每层各有多高的证据门槛，有效期多长，谁可以写入。
- **变化**：过去的观点、现在的观点和模型推测分开保存（已在智能处理规范中，该文档不在仓库中）；冲突时怎么提示你。
- **注入方式**：常驻的核心画像要小、有上限；其余按需检索。
- **整理与审阅**：定期把候选提炼成长期记忆，并给你一份可审阅的变更说明；同一结论至少在两个独立场合出现才沉淀。
- **遗忘**：删除一条记忆或一个来源时，连带删除由它派生的内容；借助派生关系做到，并提供预演。
- **权限**：画像和人格推断默认关闭，开启要你单独确认；优先用本地模型；对外部访问方单独一个范围，默认不开放。

对比方法：在你的数据上用本地模型离线运行两三种候选做法，比如「带证据的结构化记录」「可编辑的 markdown 画像」「两者结合」，由你判断哪种更准、更有用，再写规格。

### 6.2 「你关心什么」

信号来源：

- 话题和实体出现的频率与持续时间；
- 你主动做过的动作：标记、搜索、回访、停留；
- 承诺和决定涉及的对象。

待研究：几种信号怎么加权，怎么随时间衰减，怎么区分「被动看到」和「主动关注」。

### 6.3 主动打扰

什么情况值得发通知，频率上限多少，和专注状态怎么配合。在这之前，任务结果只出现在 App 内；唯一的例外是你开启了推送的钩子（如日回顾，见 [workflows](../specs/workflows.md)），默认关闭。

### 相关的已定约束

这些约束来自其他文档，研究时必须遵守：

- 不新增模型角色，不自造 agent loop（见仓库规则 [AGENTS.md](../../AGENTS.md)）。
- 数据模型对记忆的约束：记忆不钉住原件，证据链只需往下追到它依据的派生层（见 [data-model](../specs/data-model.md)）。
- 本阶段不做：人格推断、记忆的自动整合、会前简报之外的主动打扰（见 [roadmap](../roadmap.md)）。
