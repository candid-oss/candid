# 数据模型：分层、证据分级与存储预算

**中文** · [English](data-model.en.md)

**状态**：部分实现。分层、内容寻址去重、WebP 截图、录音 AAC、派生 JSON 压缩、截图预算和 v8 到 v10 的瘦身已实现；证据分级、精简记录、用量统计、策略表和日志保留期未实现。

本文规定数据的**骨架与策略**：分层、证据分级、保真度阶梯、去重、存储预算、省空间的存储方案、删除与压缩的连带关系、从 v8 起的升级路径。不规定具体表结构和字段，见 [存储规格](storage.md)；不规定整理层的流程，见 [整理层规格](curation.md)；不规定查询接口，见 [查询规格](query.md)。现状测量和验证结果见 [存储实测](../research/storage-measurements.md)。

去重阈值、自动整理规则和编码参数属于策略，可以随时调整；schema 只保证能表达它们。

<a id="overview"></a>

## 1. 概览

数据按五层存放，越往上越可以丢弃重算；空间主要花在截图和录音原件，所以治理的重点是原件的编码、去重和按级别降级，同时让每次精简都留痕、不破坏上层引用。

| 层 | 例子 | 治理方式 | 状态 |
|---|---|---|---|
| 原件 | 截图、录音、附件字节 | 内容哈希去重；WebP/AAC 编码；按预算降级 | 部分实现 |
| 记录 | 窗口切换、邮件、发给 AI 的话 | 采集时去重；日志按保留期清理 | 部分实现 |
| 派生 | OCR、转写、片段、抽取 | 可删除重算 | 已实现 |
| 记忆 | 人物、事实、承诺 | 有修订，链到证据 | 已实现 |
| 纠正 | 改名、合并、删除决定 | 独立保存，重算不覆盖 | 已实现 |

本节以下各节的状态见各节标注，汇总见[未实现与待定](#open)。

## 2. 初期功能与所需数据

第一版做扎实前五项，后两项只留位置：

| 功能 | 典型问题 | 需要的数据 |
|---|---|---|
| 回忆与检索 | 「上周和某某聊过预算吗」 | 记录、段落全文索引、人物 |
| 给 agent 的上下文 | 「我在做什么、最近关心什么」 | 片段摘要、当前状态、小而精的画像 |
| 承诺与待办 | 「我答应过谁什么」 | 从片段抽取的承诺，带出处和处理状态 |
| 日回顾 | 「今天干了什么」 | 片段、时间统计 |
| 人物和项目页 | 「和某某的所有往来」 | 实体、别名、提及 |
| 画像与偏好（留位置） | 「我喜欢怎样的回复」 | 长期记忆，证据门槛高 |
| 主动建议（留位置） | 「现在该提醒什么」 | 以上各层加注意力信号 |

这些功能需要的数据高度重合：带出处的记录、片段、实体、抽取结果。schema 围绕这几样东西设计，不为单个功能建表。

<a id="principles"></a>

## 3. 原则

1. **记录可以精简，但每次精简都留痕。** 原件和记录允许按规则降级或删除，前提是：写下精简了什么、按哪条规则、何时、省了多少；引用它的派生内容和记忆仍然成立，只是出处标明「原件已压缩为文字」或「原件已删除」。（留痕未实现：精简记录表不存在，见第 6 节）
2. **去重分三个时机**：采集时不写重复的（画面没变、文字没新内容）；入库时按内容寻址合并（同一份字节、同一段文字只存一次）；事后整理时合并近似的（相邻的近似截图、近似段落族）。（各时机的状态见第 7 节）
3. **规则是数据，不写进 schema。** schema 提供分级、保真度、精简记录和用量统计这些「挂钩」；具体策略（多久降级、阈值多少）存成可修改的策略行，由核心的整理任务执行。（未实现：当前阈值是代码常量）
4. **你的标记和纠正优先于任何自动规则。** 被你钉住的内容、你的纠正直接指向的证据，自动整理不会动。（未实现：没有钉住机制，截图预算只按年龄和是否已有文字排序）
5. **派生内容可以删掉重算，你的纠正不会被重算覆盖。**（已实现：`corrections` 独立成表，删除按墓碑流程清理派生内容）
6. **大段内容只存一份。** 正文进段落表，二进制进原件仓库；其他地方只存引用和区间，不存副本。（已实现，见第 7、9 节）

<a id="layers"></a>

## 4. 分层

| 层 | 内容 | 可变性 |
|---|---|---|
| **原件** | 截图、录音、附件的字节，按内容哈希存放 | 字节不改；可以被更省空间的表示替换（见第 6 节） |
| **记录** | 来源上报的事实：窗口切换、收到邮件、你发给 AI 的话 | 内容不改；时间范围只能延长（合并重复时）；可以按规则删除 |
| **派生** | OCR、转写、片段、抽取结果、实体候选、索引 | 可以整体删除后重算；必须写明生成者、模型、提示词版本、置信度 |
| **记忆** | 整合后的人物、事实、偏好、承诺 | 有修订记录；每条都链接到下层证据 |
| **纠正** | 你的改名、合并、标记、删除决定 | 独立保存，重算后仍然生效 |

OCR 和转写属于派生，不属于记录：它们由原件经模型生成，换了模型可以重算。截屏片段的输入目前仍放在 `store_meta` 的 `screen.input/…` 键里（已瘦身为引用，见第 12 节），尚未迁入派生层的表（未实现）。

<a id="tiers"></a>

## 5. 证据分级（未实现）

每条记录和每个原件都有一个**保留级别**，决定自动整理时的先后和底线。代码里没有 `events.tier`、`tier_by` 和 `blobs.tier`，也没有按级别执行的整理任务。

| 级别 | 含义 | 自动整理 |
|---|---|---|
| `pinned` 钉住 | 你手动标记的，或你的纠正直接指向的 | 不动 |
| `key` 关键 | 被片段或抽取结果当作主要证据 | 排在普通之后处理，底线由策略决定 |
| `normal` 普通 | 一般记录 | 按策略降级 |
| `ephemeral` 临时 | 没有新内容的重复帧、界面固定文字为主的截图、被合并掉的近似项 | 最先清理 |

- 级别由规则计算，你可以手动覆盖；手动覆盖记为纠正，规则重算不会改掉。
- 引用关系变化时级别随之上调；引用消失后可以回落。
- **记忆不要求对应到具体的文字或截图。** 一条关键事实往往是从许多片段、多次过程里归纳出来的，它的证据是片段和抽取结果这些派生内容，而不是某一张图。所以记忆不会把原件钉住，原件被压缩或删除也不影响记忆成立；证据链只需要能往下追到它实际依据的那一层。关键证据不设固定底线。
- 级别也作用于记录的原件：同一张截图被多条记录引用时，取最高的级别。

<a id="fidelity"></a>

## 6. 保真度阶梯与精简记录

原件按类型有一条保真度阶梯，自动整理只会沿阶梯往下走：

| 类型 | 阶梯（从高到低） | 状态 |
|---|---|---|
| 截图 | 入库即为 WebP（见第 9 节） → 缩略图 → 只留文字（OCR 结果保留） → 只留记录元数据 | WebP 已实现；「只留文字」已实现（截图预算）；缩略图未实现；只留元数据未实现 |
| 录音 | 处理用的 WAV（处理完即删） → AAC（见第 9 节） → 只留转写 → 只留记录元数据 | WAV 到 AAC 已实现；只留转写、只留元数据未实现 |
| 附件、文档 | 原件 → 只留提取的文字 → 只留元数据 | 未实现 |
| 派生 JSON | 结构化入表后删除文件；必须保留的用压缩格式存放 | 压缩存放已实现；入表后删除文件未实现 |

每一次降级都写进 **精简记录**（`reductions`）：对象、原保真度、新保真度、规则编号、时间、前后字节数。精简不可撤销，所以执行前要能**预演**：会释放多少空间、影响哪些条目、哪些引用会变成「只剩文字」。

精简记录和预演都未实现（`reductions` 表不存在）。现有的「只留文字」降级由 `screenshot_budget.rs` 执行：删除截图的 `original` 原件，保留事件、OCR 文字、AX 证据和元数据；释放的字节数和张数累计在 `store_meta`（`screenshot_budget.freed_bytes`、`screenshot_budget.freed_screenshots`），并出现在应用统计里，不是逐条记录。

## 7. 去重

| 时机 | 做法 | schema 需要的支持 | 状态 |
|---|---|---|---|
| 采集时 | 画面和上一张相同（感知哈希距离在阈值内）就不存新图，改为延长上一条记录的时间范围并计数 | 记录有 `end_ms` 和 `repeat_count`，允许只延长不改内容 | 部分实现：App 的采样策略按内容签名跳过没变的读取（`DesktopContentSignature`），连续打字按规则合并并计 `payload.merge.samples`；截图感知哈希去重和 `repeat_count` 列未实现；`events.end_ms` 已有 |
| 入库时 | 同一份字节只存一次（内容哈希）；同一段文字只存一次（段落哈希） | `blobs` 以哈希为键；`text_chunks` 以规范化哈希唯一 | 已实现（`blobs.sha256` 主键、`text_chunks.chunk_hash` 唯一） |
| 入库时 | 近似段落归族（SimHash，规则见[整理层规格](curation.md)） | 段落族表 `chunk_families` | 部分实现：屏幕文字投影里用 SimHash 给行归族（`screen_cleanup.rs`），没有 `chunk_families` 表 |
| 事后整理 | 相邻的近似截图合并为一条，只保留代表帧；被合并的降为 `ephemeral` 后按策略清理 | 原件有感知哈希 `phash`；精简记录写明合并关系 | 未实现（`blobs` 没有 `phash`；`screen_excerpt.rs` 用缩略图差异决定哪些截图送去摘录，不合并也不删除存储） |

近似合并的底线：数字、否定、代码的变化算新内容，不能被合并掉（规则在[整理层规格](curation.md)）。

<a id="budget"></a>

## 8. 存储预算

- **你设上限**：总量上限，可再按类别细分（截图、录音、文字与数据库），完全由你决定，不预设固定值。界面根据实测的压缩效果给出参考：按你最近的采集量，某个上限大约能保留多少天的截图、多少小时的录音。（部分实现：只有截图一类。App 把目标字节数（约上限的 90%）经 `POST /local/desktop/free-space` 交给核心；分类上限和天数参考未验证）
- **用量统计**：按「类别 × 保留级别 × 日期」维护用量汇总表，界面和整理任务直接读，不用每次扫描全库。（未实现：`storage_usage` 不存在）
- **超出时**：整理任务按「级别从低到高、时间从旧到新、保真度从高到低」挑选降级对象，直到回到上限以下；钉住的不动。（部分实现：截图预算从最旧的开始，先降已有文字的截图，最近 7 天（常量 `SCREENSHOT_KEEP_RECENT_MS`）的不动；无级别、无钉住）
- **先预演，再执行**：自动整理第一次触发或单次影响较大时，先给你一份预演说明；你可以设成以后自动执行。（未实现）
- **策略存为数据**：保留天数、阈值、编码参数都是策略行，改策略不需要改 schema，也不需要迁移。（未实现：`retention_policies` 不存在，现为代码常量）

## 9. 节省空间的存储方案

数值是在真实数据上实测后定的，原始数据见[存储实测](../research/storage-measurements.md)。

1. **截图存为 WebP（质量约 60）**（已实现）。12 张真实截图上，WebP 质量 60 平均约 122 KB，约为 JPEG 的三分之一，OCR 字符召回与 JPEG 质量 40、HEIC、AVIF 在同一波动范围内。选 WebP 的原因：编码快；Windows 和浏览器都能直接显示；HEIC 在 Windows 上要装扩展；AVIF 编码慢。
   - OCR 在压缩前对原始画面做；存下来的图主要给人看，以及以后需要时再识别。App 把原始像素交给 `candid encode-webp`，核心静态链接 libwebp 编码。
   - 副屏、非焦点窗口再降分辨率（未验证）。
2. **截图去重**：采集时的感知哈希去重，加上事后的相邻近似合并（未实现，见第 7 节）。
3. **截图按年龄降级（默认开启）**：临时级 7 天后清理；普通级 30 天后降为缩略图，90 天后只留文字；关键级 90 天后降为缩略图。天数是策略，可在设置里改或关闭；超出存储上限时第 8 节的预算优先。（未实现：没有按年龄的自动降级；只有超出上限时的预算降级）
4. **录音**：
   - 目前的实现：新的 Mac 录音先写 PCM WAV 并分片，转写和说话人分析读 WAV，处理完后核心把原件换成 AAC（`audio/mp4`，单声道，48 kbps，采样率为分片自身采样率且不低于 16 kHz）并删除 WAV；编码用系统 `afconvert`，在存储锁之外运行，换原件是一次原子替换。只处理导入时带 `compact_to` 的新分片（已实现）。
   - 设计目标：Mac 边录边写成 AAC（分片 MP4，每秒定稿一次），不再先写 WAV；意外退出时最后一个未定稿的片段之前都能恢复；磁盘上按 10 分钟一个分段，用户看不到分段。（部分实现：App 已有逐步写入的分片 AAC 迹象，边录边写和 10 分钟分段未验证）
   - 选 AAC（`.m4a`）：Mac 和 Windows 都有系统自带编码器；转写模型识别前重采样到 16 kHz 单声道，更高采样率用不上；48 kbps 约为 WAV 的十五分之一。不选 MP3（低码率最差）；Opus 更小但 Mac 上要带编码库。
   - **放行条件**：同一段录音压缩前后，转写结果基本一致，且声纹匹配分数下降不超过阈值。声纹识别本身信度偏低，要先把它的基线做可靠，这一条才有判别力。（未验证）
   - 旧的 WAV 分段由后台转换转成 AAC（已实现，见第 12 节）。
5. **数据库瘦身**：
   - `store_meta` 只放小配置；截屏片段的输入和修订进派生层的表，不再存两份。（部分实现：修订已删除、输入已瘦身为引用；输入仍在 `store_meta`，未迁入派生表。`settings` 表未建，`store_meta` 仍兼作配置）
   - 证据定位只存段落编号和字符区间，不存正文。（已实现：`screen-selector/2`）
   - 同步进度只存位置，不存内容。（部分实现：AI 会话条目已有 `agent_session_entries`、`agent_file_counts` 两张检查点表；旧内联进度的转出和路径哈希去重未验证）
   - 派生 JSON 用压缩格式存放（已实现）：raw DEFLATE（RFC 1951），blob 的 mime 为 `application/json+deflate`，后缀 `.json.deflate`，`sha256` 是压缩后字节的哈希；新写入的即压缩，旧的由后台分批转换（`json_blobs.rs`、服务层 `json_compaction.rs`）。旧设计里写的「zstd」没有采用。派生 JSON 入表未实现。
6. **日志保留期**：变更流在所有订阅方确认后压缩；访问日志超过 N 天后汇总成按天、按访问方的统计；AI 会话条目按来源的保留设置清理。（未实现：`changes`、`access_log` 只增不减；`sources.retention_days` 字段存在，清理逻辑未验证）
7. **旧存储退役**：只保留一个数据根目录；旧桌面台账和旧媒体库在转换后删除，核心里对应的迁移和对账代码一并删除。（部分实现：台账已在作者本机移出资料库；`migration.rs`、`desktop.rs` 里的迁移与切换代码仍在，`durable.rs` 里的旧媒体表仍建）
8. **WAL 上限**：SQLite 的 `journal_size_limit` 设为 64 MB，打开库和关闭时截断 WAL（已实现，`store.rs`）。

## 11. 删除与压缩的连带关系

1. 删除或压缩前先算出受影响的集合：由目标派生的内容、引用它的记忆和纠正、会失效的索引条目。预演和执行用同一套计算。（未验证：删除流程会算受影响集合，没有预演入口）
2. **删除**：写墓碑，立即对查询和 agent 隐藏；取消相关作业；删除派生内容和索引；清理无人引用的段落和原件（`delete.rs`）。（已实现）
3. **压缩**：不写墓碑，写精简记录；原件替换为低一级的表示；引用它的证据链接标为「已压缩」，引用仍然有效。（部分实现：原件替换已有，且截图预算的文件删除遵循第 2 点的顺序，先事务内删行、提交后删文件；精简记录和「已压缩」标记未实现）
4. 迟到的作业在提交前检查墓碑和精简记录，已删除或已压缩的内容不会被重新生成或还原。（部分实现：墓碑检查已有；精简记录检查随 `reductions` 一起未实现）

| 版本 | 内容 | 状态 |

| v10 | 片段输入和证据定位不再逐行重复事件 ID 和段落族哈希；证据定位改为 `screen-selector/2`，查询接口读取时还原成原来的格式 | 已实现（升级代码在同一条链上；v10 专项测试未验证） |
