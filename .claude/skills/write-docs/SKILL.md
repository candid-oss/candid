# 写文档

规则的正文在 `docs/README.md` 的「文档标准」。这里是操作步骤。

## 1. 先定种类

| 要写的内容 | 放哪 | 语言 |
|---|---|---|
| 产品方向、做不做 | `docs/product.md`（只有主人拍板后才改） | 中文 |
| 模块、依赖方向、接缝、欠账 | `docs/architecture.md` | 中文 |
| 所有改动都要守的规则 | `docs/engineering.md`，摘要进 `AGENTS.md` | 中文 |
| 对外承诺及守护它的测试 | `docs/contracts/README.md` 加一行 | 中文 |
| 一个模块现在的行为 | `docs/specs/` 里对应的规格 | 中英文两版 |
| 一个结构性决定 | `docs/decisions/NNN-标题.md`，从 025 起编号 | 中英文两版 |
| 正在做的事、进度、待决定的问题 | `docs/plans/` | 中文 |
| 怎么构建和运行某一块 | 那个目录的 README | 中英文 |

内容跨两种时拆开写，用链接连起来。不要新建第七种文档。

## 2. 写的时候

- 规格只写现在为真的。没实现的标「未实现」，没有测试支撑的标「未验证」。进度和日期流水写进计划，不写进规格。
- 一个事实只在一处写，别处链接过去。
- 引用别的文档必须给能点开的链接；不在仓库里的文档不引用。
- 面向主人的段落先给结论，说人话，不贴代码。
- 计划做完后删掉，把结论并入规格或决策记录。

## 3. 写完

```bash
python3 scripts/check_docs.py
```

它检查链接、中英文成对、规格与决策记录是否列进 `docs/README.md`。新建规格或决策记录后记得在 `docs/README.md` 的两段表格里各加一行。
