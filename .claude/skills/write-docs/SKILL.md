# 写文档

规则的正文在 `docs/standard.md`，动手前读一遍第 3 至 7 节。这里是操作步骤。

## 1. 先定种类

| 要写的内容 | 放哪 | 语言 |
|---|---|---|
| 一个主题现在的行为和规则 | `docs/specs/<主题>.md` | 中英文两个文件 |
| 和主人讨论出的一个决定 | `docs/decisions/log.md` 加一行 | 中文 |
| 影响结构、难以反悔的决定 | `docs/decisions/NNN-<标题>.md`，从 025 起编号 | 中英文两个文件 |
| 一件正在做的事：目标、步骤、进度 | `docs/plans/<名字>.md`，做完删除 | 中文 |
| 一次调研、实测、对照实验 | `docs/research/<名字>.md` | 中文 |
| 合并进主分支的一个改动 | `docs/changelog.md` 的「未发布」加一条 | 中文 |
| 要做但还没做的事、已知问题、要主人决定的问题 | `docs/roadmap.md` | 中文 |
| 对外承诺及守护它的测试 | `docs/contracts/README.md` 加一行 | 中文 |
| 模块、依赖规则、接缝、欠账 | `docs/architecture.md`（改结构要先有决定） | 中文 |
| 所有改动都要守的规则 | `docs/engineering.md`，摘要进 `AGENTS.md` | 中文 |
| 一个新术语 | `docs/glossary.md` | 中文 |
| 怎么构建和运行某一块 | 那个目录的 README | 中英文 |

内容跨两种时拆开写，用链接连起来。不新增文档种类。

## 2. 写规格

- 文件头：标题、语言切换行、一句话的状态行（只用：已实现、部分实现、未实现、设计中、已废弃）、一到三句的范围段。
- 固定章节：概览、正文各节、实现位置（代码文件与测试文件）、未实现与待定、来源。
- 每个二级标题上一行写稳定锚点 `<a id="小写-连字符"></a>`。标题可以改，锚点不改。
- 写规则用陈述句。不写日期流水、进度、「下一步」、实验数据。
- 正文默认是已实现的行为。例外在句末标 `（未实现）`、`（未验证）`、`（已废弃）`，并列进「未实现与待定」。**写状态之前去代码里查**；查不到或没查就标未验证。
- 一份不超过两万字符（用 `python3 -c "print(len(open('路径').read()))"` 量）。超了按子主题拆成两份。
- 字段级清单指向代码或快照文件，不整段抄进来。

## 3. 引用

- 文档之间：相对链接加锚点，例如 `[入库协议](connectors.md#ingest-connectors)`。不用章节号引用别的文档。
- 代码注释里：`// See docs/specs/storage.md#events`。
- 不引用仓库里没有的文档。

## 4. 记录讨论、决定和版本

讨论 → 决定流水记一行 → 要做的进待办 → 开始做时（事情大才）写计划 → 实现并同步规格与契约 → 合并时版本记录加一条、待办里删掉。

- 决定流水一行一条：日期、决定、一两句理由、落在哪份文档。最新的在最上面。被推翻的不删，新的一行写「取代某日某条」。
- 版本记录每条写用户或后续开发者能感知的结果，不写改了哪些文件。改了契约、表结构版本的写进「内部」。
- 计划做完后删除文件，结论并入规格或决定流水。

## 5. 清理旧文档

不丢信息，只挪位置：仍成立的规则进规格；带日期的决定进决定流水；进度进版本记录；实测和调研进研究记录；待定项进待办。被拆分的旧文件改成搬迁对照页（旧章节号去了哪），不删除。

## 6. 写完

```bash
python3 scripts/check_docs.py
```

它检查链接和锚点、中英文成对、每份规格/决定/研究记录是否列进所在目录的 `README.md`、规格的状态行与长度。新建规格后记得在 `docs/specs/README.md` 加一行。
